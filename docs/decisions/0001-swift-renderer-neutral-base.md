# ADR 0001: Swiftと描画非依存の最小基盤

- 日付: 2026-11-20
- 状態: 採用（描画方式のみ未決定）

## 背景
SwiftによるiOSゲームを、2人が独立したプロトタイプとして作る。デザイン担当との検討により2D/3Dは未決定。同じ投擲条件から同じ結果を得られるようにしたい。

## 選択肢
1. SwiftUI + SpriteKit に最初から固定
2. SwiftUI + RealityKit に最初から固定
3. SwiftUI 最小アプリ + Swift Package の共通ルール（採用）

## 決定
3を採用し、2D/3Dエンジンは試作で判断する。ルール計算をUIや描画フレームに従属させない。Xcodeプロジェクトの再現性のためにXcodeGenを採用する。

## 利点・欠点
- 利点: 両プロトタイプを公平に比較しやすい。ロジックを単体テストできる。
- 欠点: 描画エンジン統合時に接続コードが必要。XcodeGenをインストールする必要がある。
- 代替: `.xcodeproj` を直接管理する方法もあるが、ここでは設定差分を読みやすくする方を優先した。

## 見直し条件
描画方式決定後、モデル/物理表現との境界が不自然な場合、またはプロジェクト生成の運用負担が上回る場合。変更時は検証と移行計画を記録する。
